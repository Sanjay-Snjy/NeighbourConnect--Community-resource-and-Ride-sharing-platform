# NeighbourHub Backend Deployment

## Overview

This is the Django REST Framework backend for NeighbourHub, deployed on Render with a managed PostgreSQL database.

## Deployment on Render

### Using Blueprint

The `render.yaml` file defines a Render Blueprint that automatically provisions:
- A web service running Django with gunicorn
- A managed PostgreSQL database (free tier)
- Environment variable management
- Automatic migrations on each deploy

### Manual Setup

If you prefer manual setup:

1. **Create a web service**:
   - Root directory: `backend`
   - Build command: `./build.sh`
   - Start command: `gunicorn config.wsgi:application`

2. **Create a PostgreSQL database**:
   - Database name: `neighbourhub`
   - Plan: free

### Required Environment Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `DJANGO_SECRET_KEY` | Django secret key | (auto-generated by Render) |
| `DJANGO_DEBUG` | Debug mode | `False` |
| `DJANGO_ALLOWED_HOSTS` | Allowed hosts | `neighbourhub-api.onrender.com` |
| `CORS_ALLOWED_ORIGINS` | CORS allowed origins | `https://your-frontend.vercel.app` |
| `CSRF_TRUSTED_ORIGINS` | CSRF trusted origins | `https://your-frontend.vercel.app` |
| `DATABASE_URL` | Database connection URL | (auto-injected by Render) |
| `USE_S3` | Enable S3 media storage | `False` |

### Health Check

The health check endpoint is available at:
- `GET /healthz/` returns `200 ok`

### Database Migrations

Migrations run automatically on every deploy via the `release` phase in the `Procfile`.

## Configuration

### Environment Variables

Create a `.env` file from `.env.example` and adjust as needed. Never commit secrets.

### Build Script

The `./build.sh` script:
1. Installs Python dependencies
2. Collects static files
3. Runs database migrations

## Local Development

For local development:

1. **Create virtual environment**:
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Windows: .venv\Scripts\activate
   ```

2. **Install dependencies**:
   ```bash
   pip install -r requirements.txt
   ```

3. **Configure environment**:
   ```bash
   cp .env.example .env
   ```

4. **Run the server**:
   ```bash
   python manage.py runserver
   ```

## Troubleshooting

### Health Check Fails

Check if the database is properly configured by running:
```bash
python manage.py check --deploy
```

### Static Files Issues

Ensure `collectstatic` runs properly during build. The `./build.sh` script handles this.

### CORS Issues

Check that `CORS_ALLOWED_ORIGINS` includes your frontend domain.

## Monitoring

## Security Considerations

- Use HTTPS in production
- Set `DJANGO_DEBUG=False`
- Configure proper CORS and CSRF settings
- Use strong secret keys
- Consider enabling S3 for media storage
